# 质量审查清单（Review Checklist）

## 概述

本文档是 Phase 3（slide-reviewer）的完整审查清单。每生成一页 SVG 后，必须逐项执行以下检查。发现问题必须修复后再继续下一页。

**修复流程：** 发现问题 → 定位具体元素 → 计算正确坐标 → 修改 SVG → 重新检查。**最多迭代 2 次**，仍有问题则简化布局。

---

## 1. 溢出检查

- 任何元素的右边 x+width > W×97%？ → 缩小或左移
- 任何元素的底边 y+height > H×96%？ → 缩小或上移
- 文字是否可能超出容器边界？（中文字数 × 字宽 > 容器宽度）→ 换行或缩字号

---

## 2. 重叠检查

- 同一 `<g>` 内，相邻 `<text>` 的 y 差值 ≥ 行高？ → 增大间距
- 是否有不透明图形出现在 `<text>` 之后？ → 调整顺序
- 相邻组件之间是否有 ≥ 20px 间距？ → 增大间距

---

## 3. 空白检查与垂直居中（严格执行）

- 内容区是否有 > H×15% 的连续空白？ → 必须填充内容或调整布局
- 右下角、左下角是否有明显空洞？ → 添加 KPI 卡片、标签云或装饰
- 内容区底部是否有 > 150px 的未使用空间？ → 扩大组件高度或添加底部辅助组件
- 左右分栏布局中，任一栏底部是否有 > 20% 的空白？ → 补充内容或扩大组件

### 垂直居中量化验证（必须执行）

1. 找到本页最后一个实质内容组件（不含页脚/页码）的底边 y 值
2. 计算：上方留白 = 第一个组件顶边y - 162（内容区起始y）
3. 计算：下方留白 = 961（内容区结束y）- 最后组件底边y
4. 如果 下方留白 - 上方留白 > 80px → **必须修复**：将所有组件整体下移 (下方留白-上方留白)/2 像素
5. 如果 最后组件底边y < 864（H×80%）→ **必须修复**：增大组件高度、增大间距、或添加底部辅助组件

**常见错误模式：** 组件从 y=170 开始紧凑排列，总高度只有 500px，底部留白 300px+ → 这是最常见的错误，必须使用自适应间距公式重新分布

---

## 4. 区域内部填充检查（严格执行）

- 每个布局区域（左栏/右栏/主体区/底部区）内部的内容填充率 ≥ 75%？
- 图表组件是否独占大区域却只有少量数据项？ → 必须搭配辅助组件（数据标注、KPI、说明文字）
- 柱状图柱子间距是否 ≤ 柱子宽度 × 1.5？ → 间距过大说明数据项不足，需增加数据维度
- 饼图/环形图旁边是否有图例 + 数据标注？ → 不能只有一个孤零零的饼图
- 标签云是否 ≥ 3 行？ → 不足则增加关键词

---

## 5. 对称性检查（严格执行）

- 多列布局中，各列的项目数量是否相等？ → 不等则必须调整内容项数量
- 卡片行中的卡片是否等宽等高？ → 不等则统一尺寸
- 网格布局中，所有格子是否都有内容？ → 空格子必须填充
- 左右分栏中，两栏的内容高度差是否 < 15%？ → 差距过大则补充短栏内容

---

## 6. 对比度检查（暗色主题）

- 文字颜色亮度 ≥ 背景亮度 + 40%？
- 图表柱子/线条在背景上清晰可见？

---

## 7. 图表精度检查

- Y 轴刻度标签 y 坐标 = 对应网格线 y + 4px？
- 柱子高度 = (数据值/最大值) × 图表高度？
- 饼图扇区角度之和 = 360°？

### 环形图/饼图专项检查（有环形图/饼图时必须执行）

- 所有百分比之和 = 100%？
- 每个扇区的 startAngle 是否 = 上一个扇区的 endAngle？（累加连续性）
- 每个坐标点是否用 sin/cos 公式计算？（x = R×sin(θ), y = -R×cos(θ)）
- large-arc-flag：扇区角度 > 180° → 1，≤ 180° → 0，恰好 180° → 1？
- 外弧 sweep-flag = 1（顺时针），内弧 sweep-flag = 0（逆时针）？
- 相邻扇区端点坐标一致？（扇区 A 的外弧终点 = 扇区 B 的外弧起点）
- 最后一个扇区的终点 = 第一个扇区的起点 (0, -R)？
- **快速验证：** 把所有扇区的角度跨度加起来是否 = 360°？

---

## 8. 时间轴轴线检查（时间轴页面必须执行）

**⚠️ 这是时间轴页面最常见的错误 — 缺少主轴线。必须逐项验证：**

- **代码搜索验证：** 在 SVG 代码中搜索 `stroke-width="4"` 或 `stroke-width="3"`，是否出现在一个 `<line>` 元素上？ → 没有 = 缺少主轴线，必须添加
- 该 `<line>` 的 x1/x2（水平）或 y1/y2（垂直）是否跨越所有节点的范围？ → 不是则修正坐标
- 该 `<line>` 是否在 SVG 中位于所有节点 `<circle>` 之前（即先绘制）？ → 不是则调整顺序
- 该 `<line>` 是否有 `marker-end="url(#timeline-arrow)"`？ → 没有则添加
- `<defs>` 中是否定义了 `#timeline-grad` 和 `#timeline-arrow`？ → 没有则添加
- 节点之间的虚线连接（stroke-dasharray）是"节点到卡片的分支线"还是"主轴线"？ → 虚线不能作为主轴线，主轴线必须是实线
- **快速视觉验证：** 如果把所有节点和卡片删掉，页面上是否还剩一条明显的粗线？如果没有，就是缺少主轴线
- **代码结构验证：** `</g><!-- background -->` 之后的第一个非空元素是否是 `<line ... stroke-width="3"` 或 `stroke-width="4"`？如果不是，说明主轴线位置不对或缺失

---

## 9. 页面风格多样性检查（多页 PPT 适用）

- 目录页是否根据主题选择了对应的变体风格？ → 不能所有主题都用竖条编号式
- 同类型页面（如多个内容页）是否使用了不同的布局变体？ → 连续 3 页不能相同
- 封面页和结束页的视觉风格是否呼应但不完全相同？ → 应有变化

---

## 10. 箭头方向检查（流程图页面必须执行）

- 所有 `<line>` + `marker-end` 的箭头方向是否与流程方向一致？
- S 型流程图：第一行 `<line>` 的 x1 < x2（箭头指右）？第二行 `<line>` 的 x1 > x2（箭头指左）？
- 折返连接线（`<path>`）的终点是否在第二行最右侧卡片附近（而非最左侧）？
- **快速验证：** 沿着箭头方向走一遍流程，步骤编号是否从 01 递增到最后一步？如果中间出现编号跳跃或倒退，说明箭头方向错误
