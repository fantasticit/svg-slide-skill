# 布局系统（Layout System）

## 概述

一页幻灯片 = 布局骨架 + 多个组件的组合。布局骨架定义页面的空间划分方式，每个区域可以填入不同的组件。

## 5 种布局骨架

### 1. full-page（全屏布局）

仅用于：封面、过渡页、结束页、金句页。允许单一焦点。

**变体：**

| 变体 | 结构 | 适用 |
|------|------|------|
| A. 居中聚焦 | 标题居中 + 上下对称装饰 | 封面、结束页 |
| B. 偏移构图 | 标题偏左/偏上 + 右下大面积装饰图形 | 过渡页、章节页 |
| C. 全屏背景 + 底部信息条 | 大面积渐变/图片背景 + 底部半透明信息栏 | 封面（有背景图时） |
| D. 竖排东亚风 | 竖排艺术字 + 侧边装饰 | 古典/文化主题封面 |

```
变体 A（居中聚焦）          变体 B（偏移构图）
┌───────────────────┐      ┌───────────────────┐
│     [装饰]        │      │ [标题]             │
│                   │      │ [副标题]    [大面积 │
│   ◆ 艺术字标题 ◆  │      │             装饰   │
│     ── 分割线 ──  │      │             图形]  │
│     副标题        │      │                    │
│     [装饰]        │      │                    │
└───────────────────┘      └───────────────────┘
```

### 2. title-body（标题 + 主体）

最常用的布局。标题区占顶部 ~120px，主体区域放置组件组合。

**变体：**

| 变体 | 结构 | 适用 |
|------|------|------|
| A. 单区域满铺 | 主体区放一组横向排列的组件 | 图表 + 侧边说明 |
| B. 上下两行 | 主体区分上下两行，各放不同组件 | 主图表(上) + KPI/摘要(下) |
| C. 左主右辅 70:30 | 主体区内左侧大组件 + 右侧窄栏注释/标签 | 大图表 + 侧边数据标注 |
| D. 网格 2×2 | 主体区分四个等大区块 | 四个并列的小组件/卡片组 |
| E. 瀑布流 | 主体区内组件从上到下依次排列，宽度交替 | 内容丰富的叙事页 |

```
变体 B（上下两行）           变体 D（网格 2×2）
┌───────────────────┐      ┌───────────────────┐
│  标题              │      │  标题              │
├───────────────────┤      ├─────────┬─────────┤
│  [主图表/SmartArt] │      │ [组件A] │ [组件B] │
│  (占 65% 高度)     │      │         │         │
├───────────────────┤      ├─────────┼─────────┤
│  [KPI×4 / 摘要行]  │      │ [组件C] │ [组件D] │
│  (占 35% 高度)     │      │         │         │
└───────────────────┘      └─────────┴─────────┘
```

### 布局选择决策

```
封面/过渡/结束/金句 → full-page（选变体 A-D）
需要对比/并列展示   → title-split（选变体 A-F）
主内容 + 底部摘要   → title-body-footer（选变体 A-D）
数据密集型          → dashboard（选变体 A-D）
其他               → title-body（选变体 A-E）
```

**⚠️ 多样性强制规则：同一份 PPT 中，连续 3 页不得使用相同的布局骨架+变体组合。** 如果连续出现相同布局，必须切换变体或换用其他骨架。

## 画布坐标系统

### 画布分区（基于比例，适配任意尺寸）

画布尺寸默认 1920×1080（16:9）。以下所有坐标使用**画布宽度 W 和高度 H 的比例**定义。

```
安全边距: 上 H×5.5%, 下 H×5.5%, 左右 W×5.2%
  (默认 1920×1080 → 上下 60px, 左右 100px)

标题区: y = H×5.5% ~ H×13%  (高度 ≈ H×7.5%)
  (默认 → y=60~140, 高度 80px)

内容区: y = H×15% ~ H×89%   (高度 ≈ H×74%)  ← 必须充分利用
  (默认 → y=162~961, 高度 ≈ 800px)

页脚区: y = H×91% ~ H×96%   (高度 ≈ H×5%)
  (默认 → y=983~1037)

可用内容宽度: W × 89.6%  (默认 → 1720px)
可用内容高度: H × 74%    (默认 → 800px)
```

**换算示例：**

| 画布 | 安全边距(上下/左右) | 标题区 | 内容区 | 页脚区 |
|------|-------------------|--------|--------|--------|
| 1920×1080 | 60/100 | y=60~140 | y=162~961 | y=983~1037 |
| 1280×720 | 40/67 | y=40~94 | y=108~641 | y=655~691 |
| 960×480 | 26/50 | y=26~62 | y=72~427 | y=437~461 |

## 防重叠强制规则

### 1. 相邻文字行间距

同一组件内，`<text>` 元素的 y 坐标差值必须 ≥ 该字号的行高值。

```xml
<!-- ✅ 正确：16px 字号，行间距 28px -->
<text y="100" font-size="16">第一行</text>
<text y="128" font-size="16">第二行</text>

<!-- ❌ 错误：16px 字号，行间距只有 15px -->
<text y="100" font-size="16">第一行</text>
<text y="115" font-size="16">第二行</text>
```

### 2. 容器与内容的关系

容器高度 = 上内边距(25px) + 文字行数 × 行高 + 下内边距(25px)

示例：3 行 16px 文字 → 25 + 3×28 + 25 = 134px（容器最小高度 134px）

### 3. 组件间距

- 不同组件之间的垂直间距 ≥ 20px，水平间距 ≥ 24px

### 4. 时间轴/流程图节点间距

相邻节点的 x 坐标差值必须 ≥ 节点卡片宽度 + 40px

示例：卡片宽度 200px → 节点间距 ≥ 240px。7 个节点最小总宽度 = 7×200 + 6×40 = 1640px

### 5. 交替排列的卡片

上方卡片底边 y < 轴线 y - 20px；下方卡片顶边 y > 轴线 y + 20px

## SVG 层叠顺序规则

SVG 没有 z-index，后写的元素在上层。必须严格按以下顺序书写：

```
1. 背景层（最底层）
   ├─ 背景矩形 <rect>
   ├─ 背景渐变/纹理
   └─ 背景装饰（大面积几何色块、光晕）

2. 图形层（中间层）
   ├─ 图表网格线
   ├─ 图表柱子/扇区/面积
   ├─ 连接线/箭头
   └─ 卡片/容器背景

3. 文字层（最上层）  ← 文字必须最后写
   ├─ 标题文字
   ├─ 数据标签
   ├─ 图例文字
   └─ 注释文字
```

**关键规则：**
- ✅ 文字永远写在同组图形元素之后
- ❌ 禁止在文字之后绘制实心圆点、色块等不透明图形

**环形图/饼图正确写法：**
```xml
<!-- ✅ 正确顺序 -->
<path d="..." fill="#CF0022"/>          <!-- 1. 先画扇区 -->
<circle cx="..." cy="..." r="70" fill="#FFF"/>  <!-- 2. 中心白圆 -->
<text>8,621</text>                      <!-- 3. 最后写文字 -->
```

## 空间利用率要求

1. **内容区填充率 ≥ 80%**（组件+文字占据的面积 / 可用内容区面积）
2. **⚠️ 内容必须垂直居中于可用内容区，禁止内容堆在上方导致底部大片留白。**
3. **纵向分布均匀：** 利用上中下三段空间
4. **横向分布均匀：** title-split 布局左右两栏都必须有实质内容
5. **背景不能纯白/纯色：** 每页必须有背景装饰
6. **组件必须撑满分配区域：** 组件的宽高应尽量占满其所在区域，不要在区域内留大片空白

### 垂直布局策略（核心规则）

**内容在可用内容区内的垂直定位，必须按以下策略执行：**

**策略 A — 撑满式（优先使用）：**
组件和间距加起来刚好填满整个可用内容区高度。

```
可用内容区: y_start = H×15%, y_end = H×89%, 可用高度 CH = H×74%

计算方式（以 title-body-footer 为例）：
  主体区高度 = CH × 70%  (如 560px)
  间距 = 30px
  底部区高度 = CH × 25%  (如 200px)
  上下留白 = CH - 主体区 - 间距 - 底部区  (均分到顶部和底部)

  主体区起始 y = y_start + 上留白/2
  底部区起始 y = 主体区起始y + 主体区高度 + 间距
  底部区底边 y = y_end - 下留白/2
```

**策略 B — 垂直居中式（当内容总高度 < CH×80% 时使用）：**
先计算所有组件+间距的总高度，然后整体垂直居中。

```
内容总高度 = 所有组件高度之和 + 组件间距之和
顶部偏移 = (CH - 内容总高度) / 2
第一个组件起始 y = y_start + 顶部偏移

示例（1920×1080 画布）：
  CH = 800px, 内容总高度 = 600px
  顶部偏移 = (800 - 600) / 2 = 100px
  第一个组件起始 y = 162 + 100 = 262px
  最后一个组件底边 y = 262 + 600 = 862px
  → 上方留白 100px，下方留白 100px，视觉上下均衡 ✅
```

**⚠️ 禁止的做法：**
- ❌ 第一个组件总是从 y = H×15% 开始，不管内容多少（这会导致内容堆在上方）
- ❌ 组件之间使用固定的小间距（20-30px），导致内容集中在上半部分
- ❌ 底部 KPI 卡片紧贴主图表下方，下面留大片空白

**✅ 正确的做法：**
- 先计算所有组件的总高度
- 如果总高度 < 可用高度的 80%，使用策略 B 垂直居中
- 如果总高度 ≥ 可用高度的 80%，使用策略 A 撑满式，适当增大组件间距使内容均匀分布
- 组件间距应该是**自适应的**，而不是固定的 20-30px。间距 = (可用高度 - 组件总高度) / (组件数 - 1)，但不超过 60px

### 自适应间距计算公式

```
组件数量 N，各组件高度 h1, h2, ..., hN
组件总高度 = h1 + h2 + ... + hN
可用高度 CH = H × 74%

自适应间距 = (CH - 组件总高度) / (N + 1)
  // N+1 是因为顶部和底部也各留一份间距

第 i 个组件起始 y = H×15% + 自适应间距 + Σ(h1..h(i-1)) + (i-1) × 自适应间距

约束：
  自适应间距 ≥ 20px（最小间距）
  自适应间距 ≤ 60px（最大间距，超过则说明内容不足，需要增大组件或添加辅助组件）
```

**示例（1920×1080，3 个组件）：**
```
组件高度: 主图表 350px + 间距 + 副图表 200px + 间距 + KPI行 120px = 670px
可用高度: 800px
自适应间距: (800 - 670) / (3+1) = 32.5px ≈ 33px

第1个组件 y = 162 + 33 = 195px
第2个组件 y = 195 + 350 + 33 = 578px
第3个组件 y = 578 + 200 + 33 = 811px
第3个组件底边 y = 811 + 120 = 931px  (< 961px ✅)

上方留白: 33px, 下方留白: 961 - 931 = 30px → 上下基本均衡 ✅
```

### 空间填满策略（当内容不足时）

当页面内容无法自然填满 80% 面积时，按以下优先级补充：

| 优先级 | 策略 | 示例 |
|--------|------|------|
| 1 | 扩大现有组件尺寸 | 卡片高度从 150px 增加到 200px，增加内部留白和描述文字 |
| 2 | 增加组件间距（使用自适应间距） | 间距从 20px 增加到 40-50px，让内容均匀分布 |
| 3 | 增加文字描述行数 | 每个要点从 1 行扩展到 2-3 行，增加详细说明 |
| 4 | 添加辅助数据组件 | 底部添加 KPI 卡片行、迷你趋势线、进度条 |
| 5 | 添加引用/标签组件 | 底部添加引用块、标签云、图标徽章行 |
| 6 | 添加装饰性内容组件 | 底部提示栏、注释区、相关推荐区 |

**⚠️ 禁止的留白模式：**
- ❌ 内容集中在页面上半部分，下半部分空白（最常见的错误！）
- ❌ 左右分栏中一栏内容丰富、另一栏稀疏
- ❌ 卡片/列表只占区域的一半高度，下方空白
- ❌ 所有组件使用固定的 20-30px 间距，不管页面还有多少剩余空间

## 对称性规则（强制）

### 多列布局对称

多列布局（左右分栏、三栏、网格）中，**各列的内容项数量必须相等**。

**处理方式：**

| 情况 | 处理 |
|------|------|
| 内容项为偶数，使用两列 | ✅ 直接左右等分 |
| 内容项为奇数，使用两列 | ❌ 禁止！必须增加或减少 1 项使其为偶数 |
| 内容项为 3 的倍数，使用三栏 | ✅ 直接三等分 |
| 内容项不是 3 的倍数，使用三栏 | ❌ 禁止！调整项数或改用其他布局 |
| 无法调整项数 | 改用单列纵向排列或瀑布流布局 |

**示例：**
- 目录有 7 章 → 改为 6 章（合并相近章节）或 8 章（拆分大章节），然后左右各 3 或 4
- 特性展示有 5 项 → 改为 6 项（三栏×2行）或 4 项（2×2 网格）

### 卡片行对称

同一行的卡片必须：
- **等宽等高**
- **水平均匀分布**（间距一致）
- **内部结构一致**（标题位置、数值位置、描述行数统一）

### 左右分栏高度平衡

title-split 布局中，左右两栏的内容高度差不得超过总高度的 15%。如果一栏内容明显少于另一栏，必须为短栏补充辅助组件（标签云、引用块、KPI 卡片等）。

## 时间轴/流程图专项布局规则

**水平时间轴布局计算公式：**

```
可用宽度 CW = W × 89.6%
可用高度 CH = H × 74%
内容区起始 Y0 = H × 15%

轴线 y = Y0 + CH × 0.4（轴线放在内容区 40% 处）

节点数量 N，节点间距 = CW / (N-1)
  第 1 个节点 x = W × 5.2%
  最后一个节点 x = W × 94.8%

上方卡片底边 y = 轴线y - CH×0.04
下方卡片顶边 y = 轴线y + CH×0.04
卡片宽度 = 节点间距 - CW×0.025

底部辅助组件顶边 y = max(下方卡片底边) + CH×0.04
底边 y ≤ Y0 + CH
```

**溢出检查（生成前必须验证）：**
```
所有元素的 y + height ≤ H × 96%
所有元素的 x + width ≤ W × 97%
所有元素的 x ≥ W × 3%
所有元素的 y ≥ H × 3%
```

**放不下时的降级策略：**
1. 缩小卡片高度（每张卡片 2-3 行）
2. 缩小字号（正文 15px → 13px）
3. 减少节点数量（7 → 5-6 个）
4. 改用垂直时间轴布局

## 语义化分组规范

所有图形块必须用 `<g class="xxx">` 包裹，class 使用 kebab-case。

**标准 class 命名表：**

| 组件类型 | class 值 | 组件类型 | class 值 |
|---------|----------|---------|----------|
| 页面根 | `slide` | 背景层 | `background` |
| 标题区 | `page-title` | 页脚 | `page-footer` |
| KPI 卡片 | `kpi-card` | 柱状图 | `bar-chart` |
| 折线图 | `line-chart` | 饼图/环形图 | `pie-chart` / `donut-chart` |
| 雷达图 | `radar-chart` | 流程图 | `process-flow` |
| 流程步骤 | `process-step` | 循环图 | `cycle-diagram` |
| 循环节点 | `cycle-node` | 层级图 | `hierarchy` |
| 层级节点 | `hierarchy-node` | 矩阵图 | `matrix-chart` |
| 矩阵数据点 | `matrix-point` | 维恩图 | `venn-diagram` |
| 时间轴 | `timeline` | 时间轴节点 | `timeline-node` |
| 时间轴卡片 | `timeline-card` | 对比表 | `comparison-table` |
| 要点列表 | `bullet-list` | 引用块 | `quote-block` |
| 标签云 | `tag-cloud` | 人物卡片 | `person-card` |
| 图标徽章 | `icon-badge` | 图例 | `chart-legend` |
| 连接线 | `connector` | 装饰元素 | `decoration` |

**禁止：**
- ❌ 裸写图形元素（不包裹在 `<g>` 中）
- ❌ 无意义的 class（如 `g1`、`group-a`）

## 生成前自检清单

- [ ] 所有 `<text>` 的 y 坐标差值 ≥ 对应字号的行高？
- [ ] 所有容器 `<rect>` 的高度能容纳内部文字？
- [ ] 时间轴/流程图节点间距 ≥ 卡片宽度 + CW×2.5%？
- [ ] 内容区空间利用率 ≥ 80%？
- [ ] 没有大片连续空白（> H×15%）？
- [ ] 背景有装饰元素？
- [ ] **垂直居中：** 内容区上方留白和下方留白的差值 < 50px？（即内容垂直居中）
- [ ] **垂直居中：** 最后一个组件的底边 y 是否 > H×80%？（内容不能只占上半部分）
- [ ] 所有元素底边 y+height ≤ H×96%？右边 x+width ≤ W×97%？
- [ ] 时间轴轴线在内容区 40% 处？
- [ ] 每个 `<g>` 内，`<text>` 都写在实心图形之后？
- [ ] 环形图/饼图：扇区 → 中心白圆 → 文字，之后无实心图形？
- [ ] **对称性：** 多列布局中各列项目数量相等？
- [ ] **对称性：** 同一行卡片等宽等高、间距一致？
- [ ] **对称性：** 左右分栏内容高度差 < 15%？
- [ ] **填充度：** 内容是否延伸到页面底部区域（y > H×80%）？
- [ ] **填充度：** 组件之间间距是否 ≤ 40px？
- [ ] **填充度：** 是否有组件只占分配区域的一半高度？
